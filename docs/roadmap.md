# agent-army 演进路线图

> 更新于 2026-04-04

---

## 现状

架构已重构完成：`/army` slash command + 极简 rule（~10 行）+ skill 分层文档。

核心理念：**协作是按需触发的（/army），不是每次对话的默认行为。**

已完成：
- 调度者/执行者/顾问三角色分工与降级链路
- `/army` slash command 作为协作入口
- Rule 精简到基础认知+路由（~10 行）
- Skill 拆成主文件 + 3 个子文档（cc-reference.md、codex-reference.md、collaboration.md）按需加载
- 任务描述模板（目标/上下文/约束/产物）
- 验证 `~/.cursor/rules/` 全局生效
- 一键安装脚本、协作文件规范、交接模板
- 暂不采纳建议留档（docs/not-adopted.md）

## 第三阶段：走向智能调度

从"人判断派给谁"到"系统辅助判断"。

| # | 任务 | 说明 | 状态 |
|---|---|---|---|
| 3.1 | 用量感知调度 | check-ai-usage 结果接入调度决策——与"用户控制协作时机"理念冲突，降级为可选探索 | 可选 |
| 3.2 | dispatch.sh 调度脚本 | 输入任务描述自动判断派给谁——与按需协作理念冲突，不再计划 | ❌ 不再计划 |
| 3.3 | 执行结果反馈闭环 | cc/codex 完成后自动 diff + lint 检查，失败自动重试或降级 | 待设计 |
| 3.4 | 工具 review 自己 v2 | 定期让 cc 和 codex review 当前 rule/skill 体系，产出改进建议 | 待设计 |

## 优先级建议

```
立刻做    → 1.3（成本最低、堵住明显缺口）
本周做    → 1.2 + 1.4 + 2.1（babysit 是日常高频场景）
有空再做  → 第二阶段剩余（需实际使用经验指导设计）
暂不计划  → 第三阶段（与"用户控制协作时机"理念冲突）
```
