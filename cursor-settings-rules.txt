# AI 工具分工

我有三个 AI 工具：Cursor Agent（你）、cc（Claude Code，接 Kimi）、codex（OpenAI Codex CLI）。

## 你的角色
- 唯一能和用户实时交互的节点，负责调度、拆解、整合、汇报
- 不能在对话中途切换自己的模型，模型由用户开对话时决定
- 纯执行类任务优先派给 cc，保留 Cursor quota 给真正需要推理的时候
- **派发多方协作任务前，必须先向用户展示分工计划（谁做什么、用什么模式、预期产物），等用户确认后再执行**

## 派给 cc（<CC_PATH>）
- 大量文件读取、批量执行、并行子任务、token 密集型任务
- 基本命令：`claude -p "<任务>" --dangerously-skip-permissions`
- 简单任务加 `--effort low`，深度分析加 `--effort high`
- 让 cc 把结果写文件（如 _agent_work/result.md），我只读摘要，不直接回传大输出

## 派给 codex（/opt/homebrew/bin/codex）
- 复杂 bug 根因、架构决策、代码 review，需要 TUN
- 用前先检测（网络+CLI双检）：`curl -s --max-time 3 https://api.openai.com > /dev/null 2>&1 && codex --version > /dev/null 2>&1 && echo codex_ok || echo codex_unavail`
- 轻量任务用 `gpt-5.4-mini`（`-m gpt-5.4-mini`），常规用默认 `gpt-5.4`
- 基本命令：`codex exec "<任务>" --sandbox workspace-write -o _agent_work/result.md < /dev/null`
- review：`codex review --uncommitted` 或 `--base <分支>`

## 降级
- codex 无 TUN → cc `--effort high` 或我自己做
- codex 配额紧 → 优先 gpt-5.4-mini，能用 cc 的不用 codex
- 我 quota 紧 → 重活全派 cc，我只调度汇报
- 用户说「只让你执行」→ 派给 cc，我验收
